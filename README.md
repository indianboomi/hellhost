# Hell Host

Responsive dark hosting website for **Hell Host**.

## Pages
- Home — `index.html`
- About — `about.html`
- Contact — `contact.html`
- Login — `login.html`
- Sign up — `signup.html`
- Game hosting plans — `plans.html` (kept separate from VPS management)
- Owner/admin VPS control panel — `admin.html`\n- Minecraft server trial panel — `minecraft.html` (requires a configured backend and Pterodactyl host)\n- Pterodactyl setup guide — `PTERODACTYL-SETUP.md`\n- Secure Firebase/Pterodactyl API bridge — `backend/`

There is no customer-facing `vps.html` page. VPS provisioning is handled from the owner/admin control panel.

## Run in VS Code
Open the repository folder in VS Code and start it with Live Server, or open `index.html` in your browser.

## Owner and admin access

The backend uses Firebase Authentication UIDs; the owner/admin IDs are not generated by this repository.

1. Sign in to the website and open `admin.html`.
2. The panel displays the signed-in Firebase UID even if that account has not been authorized yet.
3. In the Render environment for `hellhost-discord-auth`, set:
   - `VPS_OWNER_UID` — the owner's exact Firebase UID.
   - `VPS_ADMIN_UIDS` — comma-separated Firebase UIDs allowed to create VPS instances.
4. Redeploy the Render service after changing environment variables.

The owner can access the panel and review provider status/managed VPS instances. Only UIDs listed in `VPS_ADMIN_UIDS` can create VPS instances. A user can be both owner and admin by listing the same UID in both settings.

Keep provider API tokens and the Firebase service-account JSON only in Render environment variables, never in browser code or GitHub.

## VPS provisioning status
Live provisioning remains disabled until the provider token and `VPS_PROVISIONING_ENABLED=true` are configured in Render and billing, spending limits, and abuse protections are ready. Never enable production provisioning before those controls are in place.
